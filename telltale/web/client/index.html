Start here

Telltale reads a vehicle bus and answers by composing an interface, never with a paragraph of text. A tap is not a link — it is a request that earns the next interface. Nothing on the screen was written by a model: the model may only name components from a fixed catalog and bind them to data, and anything it names that the catalog does not define is refused before it reaches a browser.

What happens when you tap
  1. The frame names an action — it cannot fetch, so naming is all it can do.
  2. The host checks that name against the served catalog, tags the request with its client id and turn number, and sends it.
  3. The server reads the bus, composes a fresh surface, validates it, and returns it.
  4. The host posts the new surface into the frame. Every step is printed in the host's activity log, refusals included.

Running it yourself — two processes, two jobs
# the API: data, composition, the gate — no pixels
uv run telltale-server

# the UI: this page, the host, the frame — no data
uv run telltale-client

# or both in one process, when one port is enough
uv run telltale

The client half holds no bus, no DBC and no validator, so reaching it buys nothing. The frame inside it is sandboxed without allow-same-origin, which makes its origin opaque: it cannot read the host page, its storage, or the API.
